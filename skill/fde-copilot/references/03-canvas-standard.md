# 03 · 画板设计标准

> 本文件是**画任何一屏之前必读**的规格。对标 techproto-platform-v5 原型文档的密度。

## 核心认知（先记住这一句）

**我们跟成熟原型文档的差距，不是屏数，是「一屏 9 样 + 多状态 + 注解」vs「只有一个标题」的深度差距。**

屏数可以慢慢加，但"一屏该写多深"这个标准，从第一屏就要立住。

---

## 一、每屏固定装 9 样

### ① 画板编号 + 定级
格式：`画板 2 · 核心`
标明这屏在整个产品里的分量（核心 / 常规 / 扩展）。

### ② 标题 + 一句话价值
不是只写页面名，要写清楚**这屏解决什么问题**。

techproto 范例：
> 项目工作台 — 一眼看清「在哪一步、卡在谁手上、我要做什么」
> 我的待办 — 跨项目「待我处理」的统一队列

### ③ 路由 URL
格式：`/projects/1`、`/todo`
标明这屏在整个产品结构里的位置，证明设计时想清楚了它的归属，不是孤立画图。

### ④ 区块摘要
一行列出这屏由哪几块组成。

techproto 范例：
> 阶段步骤条 + 「待我审」置顶卡 + 四张阶段卡（可下钻）+ 右栏时间线

### ⑤ 本版变更说明
写清楚这一版比上一版改了什么、为什么改。

techproto 范例：
> v5 变更：阶段卡升级站点三态（产出绿勾/加工中呼吸灯/等人审黄+负责角色微徽章）；下钻必带任务上下文（杜绝串台）；衔接按钮统一「下一站」语态；审核详情页增链条侧栏。

### ⑥ 浏览器地址栏 mock + 画布尺寸
格式：`https://xxx.local/projects/1` ＋ `1440 × 940`
让人一眼知道这是在什么尺寸下设计的。

### ⑦ 带真实感数据的界面
**必须用本项目自己的场景数据**（如万华化学研发 AI 创新材料里的真实痛点、部门、数据）。

**🚫 严禁照抄 techproto 的项目名、人名、客户名**（如"淮南顾北液压支架项目""陕煤集团神南产业""张售前""李专家"）。

### ⑧ 底部注解区
逐个区块解释设计意图，并引用规格来源章节。

techproto 范例：
> **阶段步骤条（§4.2）** — 需求 → 撰写 → 质检 → 沉淀；每段徽章：未开始/进行中/待我审/已完成；当前段高亮，点击进入
> **「待我审」置顶卡** — 按登录角色聚合本项目 HITL 待办；一句话说清「要做什么」+ 一键进对应审核界面

**本项目应引用**：PRD 章节号、ADR 编号、QA Gate 条目。

### ⑨ 角色视角说明
说明当前画的是谁的视角。

techproto 范例：
> 当前 R-PRE 视角；切 R-EXP 会显示规格审核 / 质检复核等

**本项目**：已定案单角色（顾问），仍需在画板上注明"顾问视角"，并标注"角色已确认为单角色（Maggie 2026-08 确认）"。

## 二、三个密度来源

这三样是 techproto 真正拉开密度的地方，**不做就达不到那个水平**。

### 密度来源 1：一屏画多个状态

同一个画板画**有数据态**和**空状态**两版，空状态连引导文案都写好。

techproto 范例（「我的待办」画板）：
- **有数据态**（1440 × 720）：列出 2 条待办，含项目名、阶段、需要做什么、更新时间、操作按钮
- **空状态**（1440 × 720）：居中 check-circle 图标 + 「暂无待处理」+ 浅色副文案「所有待我处理的事项都已完成。新任务到达时会出现在这里，并在顶栏铃铛提醒。」+ 主按钮「起草一份协议」直达起手，**不留白**

**本项目应画的典型多状态**：
- 有数据 / 空状态
- 已确认 / 待确认 / 已驳回
- 模板匹配成功 / 匹配不到行业
- 首次进入 / 已有历史

### 密度来源 2：标注已知实现问题

设计稿里如实记录实现层的偏差。

techproto 范例：
> 图标端正（实现端倾斜是 SvgIcon bug，原型画正）

**本项目可用**：Mission Room v1 的已知问题（视觉过平、CSS 嵌套写法失效等）都可如实标注。

### 密度来源 3：量化改进效果

用具体数字说明这版改了之后好在哪。

techproto 范例：
> 清 20 条混合待办：约 40 次往返降到约 8 次

## 三、数据性质标注规范（本项目强制）

因为行业模板内容目前是空白（Maggie 已确认"这块知识需要有人输入"），画板上的示例数据必须标清楚性质，否则会被误当成真实结论。

**标注三类：**

| 类型 | 标注文案 | 视觉处理 |
|---|---|---|
| 真实客户材料 | `来源：客户材料（万华化学研发AI创新沟通材料）· 已确认` | 正常呈现，绿色系状态标签 |
| 示例占位数据 | `来源：示例占位数据（非客户材料）· 待确认` | 灰色虚线框，明确区分 |
| 模板内容 | `示例模板内容，待行业专家补充` | 弱化呈现 |
| 顾问/AI 推断 | `来源：顾问推断（材料未明确注明）· 待确认` | 琥珀色系标签 |

**这条已在 Mission Room v1 实践过并验证有效**：客户原话（绿色左边框 + 「客户原话」标签 + 已确认）与编造的占位数据（灰色虚线框 + 「示例占位数据（非客户材料）」+ 待确认）视觉上明确区分。

**⚠️ 重要认知**：内容空白**不阻塞画板设计**。画板要证明的是"结构对不对"，不是"内容对不对"——用假的制造业痛点演示，和用真的专家填的痛点演示，界面设计完全一样。标注清楚即可，不影响评审。

## 四、techproto 解剖实录（供对照）

以下是从 techproto-platform-v5.html 源码中提取的「画板 2 · 项目工作台」完整结构，作为标准样本：

```
画板 2 · 核心
项目工作台 — 一眼看清「在哪一步、卡在谁手上、我要做什么」
路由：/projects/1
· 阶段步骤条 + 「待我审」置顶卡 + 四张阶段卡（可下钻）+ 右栏时间线
v5 变更：阶段卡升级站点三态；下钻必带任务上下文（杜绝串台）；
        衔接按钮统一「下一站」语态；审核详情页增链条侧栏。
https://techproto.local/projects/1        1440 × 940

[界面 mock：顶栏导航 / 项目信息 / 阶段步骤条 / 待我审卡 / 四张阶段卡 / 右栏时间线]
  ← 内含真实感数据：淮南顾北液压支架项目、陕煤集团神南产业、张售前、06-02 14:20

[底部注解区]
  阶段步骤条（§4.2）：需求→撰写→质检→沉淀；每段徽章四态；当前段高亮
  「待我审」置顶卡：按登录角色聚合本项目 HITL 待办；一键进对应审核界面
  四张阶段卡可下钻：卡片副标用白话产物名；点卡进入对应 Agent 详情（画板 3–6）
  右栏项目时间线：关键事件；下游未发生事件灰显占位，强化「下一步」感知
```

**关键观察**：
- 注解区不只是描述，还解释**为什么这么设计**（"下游未发生事件灰显占位，强化下一步感知"）
- 注解会**指向其他画板**（"点卡进入对应 Agent 详情（画板 3–6）"），形成互相引用的网
- 用词讲究白话（"卡片副标用白话产物名：需求清单/协议草稿/质检报告/归档入库"）

## 五、交付形态

**当前采用 C 方案**（用户已确认）：

1. **先做设计文档**（Markdown/Word），把 8–10 屏的内容、结构、逻辑全部写透，不做视觉
2. **内容定稿后**，再考虑做成 HTML 原型

**理由**：内容和视觉是两个独立问题，混在一起做，一旦视觉不满意，内容也跟着返工。且 techproto 那份的价值 80% 在内容和结构，不在视觉。

**关于视觉**：Maggie 从未说 aTool 的风格是最好的标准，Apple HIG、Google Material、Linear 等均可参考。视觉基调需重新选定，详见 `07-project-status.md`。
