# 04 · 画板蓝图

> 本文件是要画哪些屏、每屏什么定位、依据是什么的完整清单。每一屏都有出处，不是凭空编的。

## 推进顺序（已定，且推翻过一次原计划）

**按业务流程顺序推进，第一屏做 P1 新建企业。**

**最初的计划不是这样。** 起点判断是先做 Mission Room——理由是它是产品心脏、约束最多（ADR-007/008/009/010、QA Gate 五条全在这一屏），先啃最难的，等于把最复杂的规则体系跑通一遍，后面的屏会更容易。

**这个计划在准备落笔时被推翻了，原因是它依赖没做出来的上游数据。** Mission Room 顶部要显示"企业 · 部门"（这来自 P1 新建企业、P3 访谈设置的产出）、右栏 Next Best Move 要说"服务哪个北极星"（这来自 P2 战略假设）、进度条要显示"第 4/8 问"（这来自 P3 生成的提纲）。**如果先做 Mission Room，这些信息只能凭空编——写出来的东西没有出处，跟其余画板串不起来。**

**改成按业务流程顺序，从 P1 开始。** 上游先做完，轮到 Mission Room 时，它需要的每一项信息都能指向一个真实存在的来源，而不是我们编的占位。

**⚠️ 注意**："先做简单的屏" ≠ "简单地做"。P1 虽然只是填企业名和行业，但要回答的问题一点不少（见下文 P1 待答问题清单）。**标准立在"写多深"，不在"选哪屏"。**

## 核心 10 屏

### G0 · 全局框架 / 导航外壳

- **定位**：所有画板的容器，定义顶栏、侧栏、全局导航
- **依据**：techproto 的做法（每个画板都嵌在同一个壳里）
- **预期区块**：顶栏（产品名 + 主导航 + 当前用户）、主内容区
- **注意**：单角色，不需要角色切换器

### P0 · 企业列表 · 工作区入口

- **定位**：顾问服务多个企业时的总入口
- **依据**：PRD 1「顾问通常需要服务多个企业」
- **预期区块**：企业卡片列表（企业名、行业、访谈进度、最近更新）、新建企业按钮、搜索/筛选
- **必画状态**：有数据态 / 空状态（首次使用，引导"新建第一个企业"）
- **边界追问方向**：首次使用无任何企业时显示什么、企业数量增多后如何排序与检索、进行中与已完结的企业如何区分、某企业长期无进展是否需要提示

### P1 · 新建企业 ★ 第一屏

- **定位**：流程起点，只需企业名 + 行业
- **依据**：PRD 4.1；Interview Setup QA Gate「New enterprise requires only enterprise name + industry」「Industry template pre-fills strategic hypotheses」
- **预期区块**：企业名输入、行业选择、模板预填结果预览区、双出口按钮（"开始第一场访谈" / "先校准企业画像"）

**⚠️ P1 待答问题清单**（这些 PRD 没写，但画板必须回答——这正是密度的来源）：
- 行业列表里**没有匹配的行业**怎么办？（选"其他"？还是不让建？）
- 预填出来的假设，顾问**当场就想改**怎么办？还是必须先建完再去校准？
- 企业名**重复**了怎么办？
- ADR-004 要求模板内容标 `to_be_confirmed`——**界面上这个标记长什么样、放在哪？**
- QA Gate 说"战略解码不阻塞访谈"——**"先校准"和"开始访谈"两个按钮，视觉权重谁重谁轻？**
- 顾问建完企业**中途退出**了，下次回来看到什么？
- 模板条目的**置信度**怎么显示（见 `05-reverse-sedimentation.md`）？

### P2 · 企业工作台 · 战略假设校准

- **定位**：单个企业的中枢，看清"这家客户到什么程度了、下一步做什么"
- **依据**：PRD 3.3、ADR-001（战略解码属于 Enterprise）、HANDOFF 5.2–5.3
- **预期区块**：企业信息、战略假设区（北极星/行业痛点/核心能力/建议访谈部门，每条带来源与确认状态）、访谈列表、机会卡列表、交付物区块、系统主动建议下一步
- **关键约束**：战略解码是 nice-to-have，**不阻塞访谈**——界面上不能做成"必须填完才能开始访谈"
- **注**：X3 交付物库若不独立成页，其内容并入此屏的交付物区块
- **边界追问方向**：战略假设一条都还没校准时这屏长什么样、访谈列表为空时的引导、某场访谈中断未完成如何呈现、机会卡与交付物为空时该区块是隐藏还是占位

### P3 · 访谈设置向导

- **定位**：从"要访谈"到"进入 Mission Room"之间的准备
- **依据**：PRD 4.2、HANDOFF 9.1、Interview Setup QA Gate
- **预期区块**：部门选择、受访者角色、默认 8 问预览（按部门动态改写）、自定义问题上传、覆盖/合并选择
- **QA Gate 要求**：默认提纲 8 问分 3 组；用户可覆盖或合并自定义问题
- **边界追问方向**：选了模板未覆盖的部门时 8 问如何生成、自定义问题与默认问题冲突时覆盖还是合并的界面表达、上传的问题格式不合规如何提示、中途退出后再进入是否保留草稿

### P4 · Interview Mission Room ★ 已有 v1

- **定位**：产品心脏，顾问访谈现场盯着的那一屏
- **依据**：PRD 4.3、HANDOFF 9.2、Mission Room QA Gate（5 条）、ADR-007/008/009/010
- **现有 v1 结构**：左栏 Q&A 流 / 中栏受访者回答 / 右栏 Next Best Move + 候选需求
- **QA Gate 五条**（画板必须逐条满足）：
  1. 顾问 **3 秒内**能看到下一个最该问的问题
  2. Next Best Move 出现在**右侧行动区第一屏**
  3. 显示**为什么问、服务哪个北极星指标、补哪个槽位缺口**
  4. Case Intelligence 服务于当前问题，**不是独立案例墙**
  5. 候选需求描述显示**来源和确认状态**
- **相关 ADR**：
  - ADR-007：Next Best Move 是现场最高优先级交互
  - ADR-008：槽位确认摘要绑在 Slot 上，**不做右侧全局模块**
  - ADR-009：确认的推荐问题进入左侧 Q&A 流，成为待回答问题
  - ADR-010：Case Intelligence 内嵌于此，不独立成页
- **边界追问方向**：客户答非所问时 NBM 如何反应、顾问跳问或倒回上一问时进度条如何表现、一个槽位反复追问仍未填满如何处理、访谈超出 8 问后如何继续、AI 无法生成建议时右栏显示什么

### P5 · 访谈收尾 · 机会卡草稿

- **定位**：访谈结束的收口，把证据转成机会卡
- **依据**：PRD 4.4、HANDOFF 5.7
- **预期区块**：本场访谈摘要、识别出的多张机会卡草稿（每张带证据来源）、进入校准的入口
- **⭐ 反向沉淀触发点**：此屏需增加"发现 N 条模板里没有的行业共性，是否沉淀回模板"区块，详见 `05-reverse-sedimentation.md`
- **边界追问方向**：一张机会卡都没识别出来时显示什么、识别出的卡证据不足时如何标记、顾问想手动补一张卡的入口在哪、反向沉淀提示与机会卡提示如何排布避免信息挤压

### P6 · AI 机会卡校准（含 One Page Card）

- **定位**：把草稿卡打磨成可交付的机会
- **依据**：HANDOFF 9.3 + 9.5、ADR-005/012/013、AIOpportunityCard QA Gate
- **预期区块**：机会卡字段编辑、证据溯源、成熟度评分、状态切换（待确认/已确认/驳回）、One Page Card 呈现形态
- **关键约束**：One Page Card **不是独立对象**，是机会卡的表达形态（ADR-005）——同一份数据两种呈现，不是两套内容
- **QA Gate 要求**：一场访谈可生成多张卡；每张卡带 sourceInterviews 和 evidence；有成熟度和状态；能关联 As-is/To-be ProcessTwin
- **⚠️ 待处理**：QA Gate 要求"一次访谈能生成**多张**卡"，但目前万华材料只推导出 1 张（A 条），B 条因证据不足被排除。需要么再找一条能撑起第二张卡的痛点，要么在画板上注明"当前仅一张，多卡能力待补"
- **边界追问方向**：卡片字段被顾问改写后来源类型如何变更、驳回一张卡后它去哪里（删除还是归档）、One Page Card 与机会卡数据不一致时以谁为准、成熟度评分依据什么显示

### P7 · ProcessTwin · As-is / To-be

- **定位**：把抽象机会变成客户看得懂的改造前后对比
- **依据**：PRD 3.7、HANDOFF 9.4、ProcessTwin QA Gate
- **预期区块**：As-is 流程、To-be 流程、阶段×泳道网格、AI 介入点标记、JSON 面板（默认折叠）
- **QA Gate 要求**：
  - 流程是 stage × swimlane 网格
  - 节点必须待在 stage/lane 单元格内
  - 节点占位一致
  - AI 用 **tag** 表达，不用随意颜色
  - 决策节点是短问句
  - 箭头正交，路径样式一致
  - JSON 面板默认折叠
- **边界追问方向**：只有 As-is 尚无 To-be 时如何呈现、流程节点过多时画布如何处理、AI 介入点有多个时如何避免视觉混乱、顾问手动增删节点的交互边界

### P8 · 交付物生成

- **定位**：把机会卡+流程图打包成能交给客户的成品
- **依据**：DATA_MODEL「Deliverable: enterprise-level or opportunity-level output」
- **预期区块**：交付物类型选择、内容预览、导出

## 扩展模块
- **边界追问方向**：机会卡尚未全部确认时是否允许生成、导出格式有哪些、生成后原始机会卡再修改时交付物是否同步、历史交付物在哪里找回

### X1 · 跨企业待办中心

- **依据**：PRD 6「不让用户主动找下一步入口；系统应主动引导」+ PRD 1「顾问服务多个企业」
- **定位**：把所有企业里"我要做的"聚到一处
- **单角色前提下**：只有"我要做的"一种，**没有"等我审的"**（无专家复核）
- **必画状态**：有数据态 / 空状态（含引导文案）

### X2 · 证据追溯

- **依据**：HANDOFF 痛点 ①「访谈信息分散，难以追溯到原始证据」——**这是他们自己列的第一个痛点，PRD 却没有对应界面，是真空缺**
- **⚠️ 防超负荷设计（用户提出的顾虑，已解决）**：分两层，不做成一个大页面
  - **轻量层 · 溯源抽屉**（组件，非页面）：任何显示结论的地方（机会卡字段、Next Best Move 理由、One Page Card 每一条）旁边有「来源」标签，点一下**右侧滑出抽屉**，显示这条的证据链：原始 Q&A 片段 → 来源类型 → 确认状态 → 谁确认的 → 什么时候。看完关掉，不跳页。
  - **重量层 · 证据总览页**（独立页，低频）：按访谈筛、按确认状态筛、按来源类型筛。用于访谈收尾时全面检查"还有多少条待确认"。
- **参照**：techproto 的 G5 链条侧栏也是"组件而非独立页"，同一思路

### X3 · 交付物库

- **依据**：DATA_MODEL 有 Deliverable 对象
- **状态**：**保留，但低优先级，最后画**（用户选择保守起见保留）
- **保留的代价**：只有多做一屏的工作量，无其他副作用——不让主流程变复杂、不违反 ADR、后期要删也不影响别的屏
- **待判断**：是否存在"跨企业翻历史交付物"的场景（如做 B 公司方案时想参考给 A 公司做过的类似方案）。若无此需求，可合并进 P2 企业工作台

### X4 · 行业模板管理 ⭐ 已升级为核心

- **依据**：IndustryTemplate 是一级对象，需要维护入口
- **⭐ 升级理由**：Maggie 明确说 senior 的经验要靠模板承载，且这块知识是空白待填——**"谁来维护模板、怎么维护"因此成为产品核心能力之一，不是边角功能**
- **预期区块**：模板列表、模板详情（五个字段：行业痛点/北极星指标/核心能力/建议访谈部门/默认场景模式）、每条的来源与置信度、编辑/撤下操作
- **⭐ 反向沉淀落地页**，详见 `05-reverse-sedimentation.md`

## 已定案

### X6 · 角色 —— 单角色

**Maggie 已确认**：没有资深专家 review 这一道。

**设计影响**：
- 待办中心（X1）只有"我要做的"，不需要"等我审的"
- 机会卡确认（P6）就是顾问审 AI，不需要"提交复核""待专家审"这些状态和按钮
- 全局框架（G0）不需要角色切换器
- `rejected` 状态驳回的是 AI 的产出

**⚠️ 记录一处 Claude 早期的编造**："提交复核""待专家审"这类词**在 Maggie 的 9 份文档里一个都没有**，是 Claude 从 techproto 的多角色设计套过来的。已纠正。

## 屏数说明

**核心 10 屏 + 扩展 4 屏 = 14 屏左右**，不是几十屏。

techproto 有 25 屏，是因为它还有知识库（4 屏）、管理后台（2 屏）、待办中心、我的文档等模块，其中大部分不在本项目 PRD 范围内。**不必为凑屏数而加，但可在有依据时扩展**（如 X2 就是从他们自己的痛点 ① 推出来的，不是抄 techproto）。
