## 1. 问题来源：Maggie 指出的知识空白

Maggie 原话：
> 原来 senior 的"看一眼"变成外挂的知识库（比如做调研问卷的时候，不同的行业，他的这个北极星的一些重要指标会不一样，然后不同的业务，它的侧重点会不一样，这块目前比较多的专家知识），类似 AI 也要替代掉 senior 的角色

> 你想到这也挺好的，因为**这个现在是一个知识的空白，这块的知识确实需要有人输入**

> 比如说 2C 的行业和 2B 的行业就不一样，ex 苹果他们的卖这种电子消费的，同样销售领域 和互联网的用增 人群的划分 转化漏斗率

**核心矛盾**：IndustryTemplate 承载着"替代 senior 判断"的重任，但它的内容目前是空白，而且 PRD 里它**只能单向流出、自己永远不变**——所以只能坐等专家来写，而没人写它就一直空着。

---

## 2. 机制是什么

**一句话：让行业模板不靠专家坐着写，而是从每一次真实访谈里自己长出来。**

**PRD 现状（单向）**：
```
行业模板 → 预填企业战略假设 → 访谈 → 证据 → 机会卡
```

**加上反向沉淀（双向）**：
```
行业模板 → 预填 → 访谈 → 证据 → 机会卡
    ↑                              ↓
    └────── 回流：这个行业的新发现 ─┘
```

**具体例子**：访谈万华化学，模板里预填的制造业痛点是"预测不准/库存高/售后慢"。访谈发现真正的痛点是"实验室最优解在放大过程中会变异"——**这条模板里没有**。顾问确认这是行业普遍问题后，点"沉淀回模板"，下次新建化工企业，这条就出现在预填里。

**跑了十个化工客户之后，这个模板就是十次真实访谈养出来的，比任何专家凭空写的都准。**

---

## 3. 它解决了什么

| 问题 | 反向沉淀怎么解决 |
|---|---|
| Maggie 说"知识空白需要有人输入" | 不用等专家，访谈本身就在输入 |
| 模板是"待推翻的假设" | 推翻之后的**正确答案不该被丢掉，该回填** |
| senior 的经验要变成外挂知识库 | 这就是经验被固化的**具体路径** |
| 顾问服务多个企业 | 第 N 个客户能享受前 N-1 个客户的积累 |

## 4. 三屏落点

### P5 访谈收尾 —— 沉淀的触发点

访谈结束时，除了提示"识别出 N 张机会卡草稿"，再增加一块：

```
发现 2 条模板里没有的行业共性，是否沉淀回「化工行业」模板？

· 痛点：实验室最优解在放大过程中变异
  【来源：客户原话 | 已确认】

· 建议访谈部门：工艺工程部
  【来源：AI推断 | 待确认】

[沉淀回模板]  [仅本企业保留]  [忽略]
```

**⚠️ 关键设计：三个按钮，不是两个。**
因为有些发现是**这家企业特有的**（不该污染整个行业模板），有些才是**行业共性**。让顾问判断，系统不替他决定。

### X4 行业模板管理 —— 沉淀的落地页

模板页要能看到每一条的来历：

```
化工行业模板 · 行业痛点

· 前端探索依赖人工经验        【3 家提及】
· 放大过程结果变异            【2 家提及】
· 库存周转慢                  【初始设定，尚未被访谈印证】
```

**关键设计**：标明每条被几家企业提及过，**且可点开看是哪几家**。一家提过 vs 三家都提过，可信度完全不同——这直接对应「每个结论必须有来源和确认状态」这条原则。

### P1 新建企业 —— 沉淀的回报

预填区里，模板条目显示提及次数，让顾问知道该重点验证哪条：

```
预填战略假设（来自化工行业模板）

· 前端探索依赖人工经验    【3 家提及 · 待确认】
· 库存周转慢              【初始设定，未经印证 · 待确认】
```

**作用**：顾问一眼知道哪条更可信、哪条要重点验证。

## 5. 置信度计数规则

**这条规则经过一次推翻，记录下来是因为推翻的理由比结论本身更重要。**

**最初的设计**是给每条模板内容标一个主观等级——"置信度：高 / 中 / 低"，靠这个等级提示顾问该重点验证哪条。这个设计当时看起来是合理的：分级简单，顾问一眼能看懂轻重。

**问题在于它站不住"每个结论必须有来源"这条项目底线。** "置信度：高"这四个字，顾问没法追问"高在哪、凭什么"——它是一个黑箱判断，不是一个可核验的事实。而项目里其他所有结论（证据、机会卡）都要求带来源、可点开追溯，唯独这里例外，逻辑上不一致。

**改成客观计数**：不再评判"高不高"，只记录"被几家企业提到过"，且每条都能点开看是具体哪几家。

| 显示 | 含义 |
|---|---|
| **首次记录** | 第 1 家企业提到，还没被其他企业印证 |
| **2 家提及** | 出现第 2 家，开始有行业共性的迹象 |
| **3 家及以上提及** | 基本可以当行业普遍问题看 |
| **初始设定，尚未被访谈印证** | 建库时人工写的，还没有真实访谈支撑 |

**门槛值也经过一次修正。** 计数方案定下来后，第一版把"多家验证"的门槛设在 5 家——这个数字当时是照着消费级产品的直觉给的（多家用户反馈才算数）。但放到这个场景里站不住：**这是咨询产品，一个顾问一年可能只接触 2-3 家同行业客户，门槛设在 5 家意味着这条规则在现实中几年都不会触发一次**，等于形同虚设。改成 2 家——第二家企业提到同一个痛点，这个信号已经足够让顾问重视了。

**改完之后，客观计数相比主观分级的优势是明确的：**
1. **可追溯** —— "3 家提及"能点开看是哪 3 家，符合「每个结论必须有来源」的原则
2. **不需要算法** —— 就是计数，不涉及 AI 打分，现阶段无后端也能设计
3. **顾问自己会判断** —— 看到"首次记录"，他自然知道这条要重点验证，不需要系统替他下"高/低"的结论

## 6. 否定的处理

**这条也是先有一版会出问题的设计，后来才改对的。**

**最初的想法**很直接：一条模板内容如果被某家企业明确否定（"我们没这个问题"），那就撤下这条，不再预填给下一家企业。逻辑上似乎顺理成章——既然被推翻了，就该移除。

**但推演一个具体场景就会发现这个逻辑是错的。** 假设某家化工厂的数字化基础特别好，预测一直很准，访谈时否定了"预测不准是行业痛点"这条——**这只说明这一家企业强，不能说明"预测不准"在整个化工行业里不是痛点。** 单次否定就撤销整条，等于让一家特例把整个行业模板的判断给带偏了。**"这家企业没这个问题"和"这个行业没这个问题"是两件事，混为一谈是这版设计的根本问题。**

**改成：否定只做记录，不做撤销，且与提及次数并列展示。**

```
前端探索依赖人工经验
3 家提及 · 1 家表示不适用
【点开可见：提及的是 A/B/C，不适用的是 D】
```

顾问看到这行，自己判断这条对当前客户适不适用。**系统不替他下结论**——这跟置信度那条改动是同一个原则：黑箱式的系统判断，不如把原始数据摊开让人自己看。

**什么情况下提示撤下**：只有当否定明显压过提及时，才给温和提示，且**仍由人决定**：

```
⚠️ 这条已被 3 家企业表示不适用，仅 1 家提及。是否撤下？
[撤下]  [保留，继续观察]
```

**"撤下"不是删除**，是标记为已撤回、保留历史痕迹——符合「每个结论必须有来源和确认状态」原则，也防止误操作后无法追溯。

## 7. 污染防护

**风险**：如果顾问乱沉淀，模板会越来越脏。比如某家企业的特殊问题被误当成行业共性沉淀进去，后面每家新企业都被预填这条错的假设。

**四道防护**：

1. **沉淀必须顾问显式确认**，不能自动
2. **模板条目带提及次数**（几家企业提过）
3. **低次数条目在预填时视觉弱化**或默认折叠
4. **模板管理页支持撤下**（不是删除，是标记为已撤回，保留痕迹）

## 8. 可行性说明

**分两层看，一层可行一层不可行——这个区分很重要，因为它决定了内容空白是否阻塞设计。**

### 层一：模板的「结构」—— 完全可行，现在就能做

模板要装哪些字段，PRD 3.1 已经写死：
> 行业痛点、北极星指标、核心能力、建议访谈部门、默认场景模式

**这五个字段就是骨架，不需要任何行业知识就能定。** 画板上要显示什么、怎么排布、怎么标 `to_be_confirmed`——**这些是设计问题，不是知识问题。**

### 层二：模板的「内容」—— 现在不可行

"制造业的北极星指标具体是哪几个""2B 销售和 2C 销售的转化漏斗有什么不同"——**这些需要真正的行业专家填**，Maggie 说的"需要有人输入"就是这个意思。

### 结论：内容空白不阻塞画板设计

**画板要证明的是"结构对不对"，不是"内容对不对"。** 用一条假的"制造业常见痛点：预测不准"演示，和用一条真的专家填的痛点演示，**界面设计完全一样。**

**唯一的真实影响**：内容空白会限制"演示的说服力"，不限制"设计的正确性"。拿去给客户看，客户可能说"你这个制造业痛点写得不对"——**那是内容问题，不是设计问题。**

**处理办法**：在画板上标清楚数据性质（见 `03-canvas-standard.md` 第三节），标成「示例模板内容，待行业专家补充」。这样任何人看画板都知道：**结构是定稿的，内容是占位的。**
